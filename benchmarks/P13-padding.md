# P13 — I33 padding 机制探针(0.6B,夜间执行)

- **门**:独立进程 eager/segment 交错 5 组,丢每形状首 batch;CV≤5%。segment b17/b16 ≥1.15 且 eager ≤1.10 支持阶跃;0.6B dense 不能代替 30B MoE 在线归因。
- **口径**:0.6B TP2 paged,128 输入/80 输出、5 组交错(每组 3 轮取中位,首轮 warmup),batch=6,8,9,12,15,16,17,20,24,32;tiny MoE 用 sdpa 覆盖 b16/b17 后端路径。探针记录实际 batch、cap、tokens hash 与原始 step 时间。

  - 跨模式 token hash 逐 batch 全等(`cross_mode_tokens_equal`,覆盖 fallback 行为与 scratch-slot 契约)。
- **判定**:**0.6B 上 padding 税不可见(探针判定力不足)**——0.6B 设备计算太小,replay 固定开销主导:b9(pad 到 16)与 b8(cap=8)步时几乎相同(34.21 vs 33.94);阶跃存在但远小于门。**本探针不能证明也不能证伪 30B 的 padding 归因**;30B 归因只能由"修复后在线 A/B 差分"给出(见 `benchmarks/P13-fix.md`):若密桶+回退把在线回退收回 ≈0%,padding 税为主因成立;若收不回,段间 eager AR 串行化是主因。与 P12 的归因推断不矛盾(P12 基于 30B 在线数据,本探针只是密度不足)。
