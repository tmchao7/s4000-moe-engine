# P10 — I30 混步税判定 + chunk-2048 短 prompt 默认化决策

> 门**先冻结后跑**(2026-10-28 晚)。对照基线 = P9-P4(`benchmarks/P9-serving.md`):split=1、chunk-256,四档 ×3 全 100% SLO(std+strict),TPOT p95 @0.87 = 0.387–0.397 s(vs v4 门 0.343,+13~16%),TTFT p95 @0.87 = 1.192–1.197 s。
> 矩阵与 P9-P4 完全一致:`--mode poisson --max-qps 0.87 --fractions 0.5,0.75,0.9,1.0 --requests 128 --prompt-words 128 --repeats 3 --request-timeout-s 120`,默认生产栈(除被测变量)。

## 冻结门(跑前写,不可改)

**有效性门(每发)**:12/12 点各 128/128 `[DONE]`;prompt p50 = 137±5;rank1 存活;错误桶全 none。

**Run B(I30 判定;唯一变量 `NANOVLLM_MIXED_SPLIT=0`,chunk=256)**:
- B-门(混步税确认):0.87 档 TPOT p95 中位 ≤0.343 s(回到 v4 门内)→ 确认 I30 = I23 混步短 prompt 税;且 0.5 档 TTFT p95 不劣于基线 +5%(≤1.25 s)→ 混步关闭无 TTFT 代价。
- 判定树:TPOT 过门且 TTFT 不劣 → 决策项(默认改 or 分场景 flag,见 §判定);TPOT 过门但 TTFT 劣化 >5% → 记"税确认但拆东墙",默认保 split=1,flag 留给短 prompt 场景;TPOT 仍 >0.343 → I30 转向(P8 期累积改动二分),混步假设否定。

**Run C(chunk 默认化决策;唯一变量 `--prefill-chunk-size 2048`,split=1)**:
- C-门:四档 TTFT p95 与 TPOT p95 均不劣于基线(chunk-256)5% 以内 → 建议默认切 2048(改 `config.py:37` + api_server 默认);任一劣化 >5% → 默认不动,chunk-2048 保持 1k 场景推荐配置。
- 附带(报告项,非门):0.87 档 TPOT p95 是否顺带回到 ≤0.343(若 C 也修 I30,则两个杠杆指向同一根因——混步步长被 chunk 放大)。

## Run B 实际(split=0, chunk=256)

**Attempt 1(15:53–16:16)崩溃**:0.5 档 ×3 全 100%、0.75 档 rep1=94.5%/rep2=85.9% std(基线 100%)后,rep3 warmup 期间**服务器段错误**(rank1 `MUSA error: operation not permitted` → MCCL abort → teardown segfault core dumped;client RC=1 无 JSON)。该路径(整批混步走 prefill)自 P8 起默认关闭、线上未再被压测过。→ 按 SOP 重试 1 次判定偶发 vs 必现;**无论重试结果如何,"split=0 在 0.75 档即失稳 + SLO 掉点"已构成保留 split=1 默认的强证据**。

**Attempt 2(16:24–17:22,重试,RC=0,12/12 点)**:

| load | split=0 SLO std(r1/r2/r3) | 基线 split=1 | split=0 TPOT p95 范围 | 基线 TPOT p95 |
|---|---|---|---|---|
| 0.5 | 100 / 100 / 100 | 100 / 100 / 100 | **0.335–0.348** | 0.332–0.350 |
| 0.75 | 73.4 / 86.7 / 89.8 | 100 / 100 / 100 | 0.515–0.599 | 0.375–0.388 |
| 0.9 | 74.2 / 89.1 / 80.5 | 100 / 100 / 100 | 0.509–0.529 | 0.381–0.382 |
| 1.0 | 22.7 / 57.0 / 61.7 | 100 / 100 / 100 | 0.559–0.643 | 0.387–0.397 |

**Run B 判定(I30 收口)**:
1. **混步税假设否定**:0.5 档 split=0 的 TPOT p95(0.335–0.348)与基线(0.332–0.350)重合——TPOT p95 相对 v4 的 +13~16% 回归**不是** mixed-split 引起;关闭它拿不回任何 TPOT。
2. **关闭混步代价巨大**:≥0.75 负载 SLO 崩塌(1.0 档最低 22.7%),TTFT/TPOT 全面劣化,且 attempt1 出现服务器段错误失稳。混步拆分是高负载稳定性的必要结构。
3. **决策:`NANOVLLM_MIXED_SPLIT=1` 默认维持不动,I30 关闭该假设**;TPOT p95 回归转向"P8 期累积改动二分"重开(下一候选:容量收缩/host-sync 之外的 P8 改动逐项回滚 A/B,或 v4 时代服务端背景差异——注:v4 TPOT p95 0.327 是单跑,跨轮可比性存疑,亦可先补 v4 口径的重复测量)。
- 证据:`benchmarks/data/p10/p10_serving_split0.json`、`p10_client_b2.log`、`p10_server_b_attempt1.log`(崩溃现场)。

## Run C 实际(split=1, chunk=2048;17:35–18:26,RC=0,12/12)

SLO:12/12 点 std 全 100%(strict 仅 0.75 rep1 = 99.2%)。延迟对比(chunk-256 基线):

| load | C TPOT p95(中位) | 基线 | Δ | C TTFT p95(中位) | 基线 | Δ |
|---|---|---|---|---|---|---|
| 0.5 | 0.359 | ~0.341 | **+5.3%** | 1.136 | ~1.108 | +2.5% |
| 0.75 | 0.392 | ~0.384 | +2.1% | 1.163 | ~1.092 | +6.5% |
| 0.9 | 0.408 | ~0.381 | **+7.1%** | 1.244 | ~1.161 | +7.2% |
| 1.0 | 0.428 | ~0.391 | **+9.5%** | 1.251 | ~1.194 | +4.8% |

**Run C 判定**:C-门(TTFT/TPOT p95 均 ≤+5% 劣化)**未过**——TPOT p95 在 0.5/0.9/1.0 档中位 +5.3/+7.1/+9.5%,TTFT p95 高负载 +5~7%(chunk 变大使混步步长变粗,邻居请求的 p95 被拖)。SLO 全 100% 说明绝对影响小,但按冻结门:**`prefill_chunk_size` 默认维持 256;chunk-2048 继续作为 1k 长上下文场景的推荐配置(按场景显式开启,P9-long-context.md)**。附带:0.87 档 TPOT p95 0.407–0.449,仍高于 v4 门——与 I30 判定一致(回归既非 split 也非 chunk)。
- 证据:`benchmarks/data/p10/p10_serving_c2048.json`、`p10_client_c.log`、`p10_server_c.log`。

## 总判定

1. **I30 关闭混步税假设**:split=0 拿不回 TPOT(低负载重合、高负载崩塌+失稳);`NANOVLLM_MIXED_SPLIT=1` 默认维持;TPOT p95 相对 v4 的回归转向跨轮口径复核(v4 为单跑)+ P8 改动二分。
2. **chunk-2048 不切默认**:短 prompt TPOT p95 +5~9.5% 超门;1k 场景推荐配置维持。
3. 两个默认值决策均维持现状——本轮净产出是两个被否定的假设(负结果)与新增的 split=0 失稳证据。
